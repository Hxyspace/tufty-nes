# Tufty NES 手柄协议

CDC1 串口和 BLE 共用十字节按键 Report，以及摇杆、Home 和组合键解析。两条连接各自保留输入状态，断开其中一路不会释放另一路的按键。本机 GPIO 直接映射为 NES 按键和 Home，与远程输入合并后应用 `swapab`。USB 磁盘模式不处理手柄输入。日常操作见 [使用指南](usage.md)。

## USB 串口

CDC0（Console）用于设置，CDC1（Gamepad）用于手柄。CDC1 使用 115200 波特率，打开时启用 DTR，USB VID/PID 为 `CAFE:4025`。串口仅支持 **TGP v3**，固件和 Python 发送器需一起更新。

### 会话

每条消息以 ASCII LF 结尾，也接受 CRLF。设备在连接时发送 `#TGP:APP\n`。

```text
PC -> Tufty: #TGP:HELLO:0001:0123456789abcdef:3
Tufty -> PC: #TGP:READY:0123456789abcdef:3
PC -> Tufty: #TGP:5447500301000080808080020100000000
Tufty -> PC: #TGP:ALIVE:0123456789abcdef
PC -> Tufty: #TGP:54475003010001544750014259450000a5
Tufty -> PC: #TGP:BYE:0123456789abcdef
```

`HELLO` 中的 ID 是 4 位十六进制（1–65535，默认 0001），必须与设备 `padid` 一致。nonce 是 16 位小写十六进制，每次新会话生成；发送器只接受匹配 nonce 和版本的 READY，ALIVE/BYE 也必须匹配 nonce。新会话、断开 DTR 或关闭 Report 均释放该路输入。重复同一 HELLO 不重置按键超时、组合键计时或序列号检查。

每 120 ms 至少发送一个状态帧，输入变化时立即发送。设备每 500 ms 发 ALIVE；350 ms 无有效帧则释放按键、Home 并取消组合键计时，1200 ms 无有效帧则结束会话。PC 在握手等待或 ALIVE 超时 1200 ms 后重新握手。中立心跳不延后菜单自动休眠。

### 状态帧

二进制结构固定 **17 字节**，转成 34 个十六进制字符并包装为 `#TGP:<hex>\n`；不直接发送二进制。含前缀和 LF 的一行共 40 字节。

| 字节 | 内容 |
|---|---|
| 0–2 | ASCII `TGP` |
| 3 | 版本 `03` |
| 4–5 | controller ID，小端 |
| 6 | sequence，每次状态帧加 1，模 256 |
| 7–16 | 下文的共用十字节 Report，不带 HID Report ID |

同一会话连续相同 sequence 的帧被拒绝；心跳和关闭 Report 也必须增加 sequence。不支持的版本、错误 ID、错误长度或非十六进制数据不更新有效帧计时。状态帧不携带 nonce，必须在握手后发送。

上例第一帧为 ID 1、sequence 0、右+A；第二帧为 sequence 1 的主动关闭消息。旧版 v1/v2、无版本握手、MENU 和 END 命令已移除。PC 的 Esc 直接发送 Home 按下/松开状态，Ctrl+C 发送中立状态和关闭 Report 后退出。

## BLE HID

Tufty 作为 Central，默认扫描 HID 服务 `0x1812` 并自动连接。当前支持实体 XTARK 手柄及采用相同布局的安卓发送端；不使用串口的 ID、序列号和会话握手。指定 MAC 或恢复自动连接的方法见 [使用指南](usage.md#连接设置)。

读取 Report Map（`0x2A4B`），通过 Report Reference（`0x2908`）区分报告，并订阅 Input Report（`0x2A4D`）的 CCCD。游戏使用 **Report ID 4、10 字节 payload**，GATT 通知不带 ID 前缀；Consumer Report ID 3 不映射为 NES 输入。固件检查描述符布局后才读取。

Read 返回当前完整状态，输入变化时通知。BLE 无需心跳，不因通知静默释放输入或重连；实际断连时释放该路输入并重新扫描。实体手柄使用 LE Legacy Just Works 配对，配对信息仅存 RAM。

## 共用 Report

串口状态帧的后十字节，与 BLE 游戏报告 payload 完全相同：

| 字节 | 内容 |
|---|---|
| 0–1 | 左摇杆 X/Y，0 左/上、128 居中、255 右/下 |
| 2–3 | 右摇杆 X/Y，坐标同上，暂不控制 NES |
| 4 | 低四位方向：0 上、1 右上、2 右、3 右下、4 下、5 左下、6 左、7 左上；8–15 松开，高四位为填充 |
| 5 | 数字按钮：A=`01`、B=`02`、X=`08`、Y=`10`、LB=`40`、RB=`80` |
| 6 | 数字按钮：LT=`01`、RT=`02`、Select=`04`、Start=`08`、Home=`10`、L3=`20`、R3=`40` |
| 7–8 | RT / LT 按压程度，0 松开、255 完全按下 |
| 9 | 填充，普通状态发送 `00` |

掩码为十六进制，组合键按位 OR。初始和全部松开时发送：

```text
80 80 80 80 FF 00 00 00 00 00
```

### 游戏操作与返回菜单

NES 使用方向、A/B、Select/Start。左摇杆带回中死区，可代替十字键；十字键有输入时优先。X/Y、肩键和扳机不映射额外 NES 动作。

实体手柄的 Home 当前不发送输入，可将左右摇杆回中、松开其他按键和扳机，同时按下 **L3+R3 并保持 1.5 秒**返回菜单。触发后需松开两个摇杆按键才能继续操作。串口和安卓也可使用 byte 6 的 `10` 位直接发送 Home，松开时清除此位。按住 Home 时不能在菜单启动游戏；组合键只使用同一连接内的按键。

### 主动关闭手柄

通过串口 v3 状态帧或已订阅的 BLE ID 4 游戏报告，发送以下固定十字节消息：

```text
54 47 50 01 42 59 45 00 00 A5
```

这是主动关闭消息，必须完整匹配；普通状态不能仅靠修改填充字节请求断开。Tufty 先释放该路输入，再由传输层结束当前连接，不修改保存的设置：

- 串口结束 TGP 会话并回复 `BYE:<nonce>`，USB 端口仍然存在。脚本主动退出时不会因 BYE 再次握手，最多等 250 ms 后关闭端口。
- BLE 主动断开当前手柄并继续扫描，无需关闭手机系统蓝牙。

安卓先停止普通输入通知和广播，发送关闭消息后保留 GATT Server，等待断开回调再清理，可设置约 2 秒的清理超时。重新开启时恢复中立状态及广播，无需关闭手机系统蓝牙。完整 Report Map 及安卓发送端实现细节见安卓手柄项目的 `docs/hid-protocol.md`。
